# Third-party notices — NanoCraft

NanoCraft is a set of launcher scripts, a framebuffer EGL shim and a quick menu.
Almost everything it *distributes* belongs to other projects, listed here with
what was changed and where the corresponding source lives.

**No Minecraft code, assets, worlds or data are included or redistributed, and
none ever will be.** The game comes from an APK the user supplies themselves.
See [LEGAL.md](LEGAL.md).

The release payload is about 48 MB. Every binary in it is covered below.

---

## Ninecraft (MIT) — modified binary

`ninecraft` is a **modified build** of Ninecraft, an open-source launcher for
Minecraft Pocket Edition 0.1.0–0.11.1. It loads the user's own
`libminecraftpe.so` out of their own APK; it contains no Minecraft code itself.

| | |
| --- | --- |
| Upstream | https://github.com/MCPI-Revival/Ninecraft |
| Licence | **MIT** |
| Pinned at | commit `0d952d682d1044689eebaed98cb451a975f75a7e` |

**Modifications**, applied as source patches before compiling:

1. **Handheld input.** `src/miyoo_input.c` and its header add a reader for
   `/dev/input/event0` that publishes SDL events for Ninecraft's existing
   keyboard and mouse callbacks, because SDL's offscreen video driver has no
   input backend. This is what makes the face buttons act as a right stick.
2. **Version-check and build fixes** in `ninecraft-main.patch`, including a
   `strncmp` prefix match so a retail build suffix no longer causes
   "Unsupported Version!".

Both ship in `build/` in this repository, with the Dockerfile that applies them,
so the binary can be reproduced. MIT does not require this; it is here because a
port nobody can rebuild is a dead end.

## Mesa (MIT) — unmodified binaries

Two separate Mesa builds ship, both Mesa 20.3.5 for armhf, built from
unmodified upstream source:

| Directory | What it is |
| --- | --- |
| `mesa/` | the **llvmpipe** software rasterizer: `libEGL`, `libGLESv2`, `libglapi` and `dri/swrast_dri.so` |
| `gl/libGL.so.1` | **OSMesa** (SONAME `libOSMesa.so.8`), which SDL dlopens as its desktop-GL symbol provider |

- Upstream: https://www.mesa3d.org/
- Licence: MIT — https://docs.mesa3d.org/license.html

### LLVM (statically linked into swrast_dri.so)

llvmpipe JITs shaders, so **LLVM 7 as packaged by Debian 10 (Buster) is linked
statically** into `mesa/dri/swrast_dri.so`. It is not a separate file, but it is
redistributed all the same.

Debian records LLVM 7 under the University of Illinois/NCSA Open Source Licence.
LLVM relicensed to Apache-2.0-with-LLVM-exceptions in later versions, so **the
terms that actually apply here are the ones in Debian's `llvm-toolchain-7`
source package**, obtainable as described below.

## GNU C Library (LGPL-2.1-or-later) — unmodified binaries

`runtime/` contains **Debian 10 (Buster) armhf glibc**, unmodified:
`ld-linux-armhf.so.3`, `libc.so.6`, `libm.so.6`, `libpthread.so.0`,
`libdl.so.2`, `librt.so.1`, plus `libgcc_s.so.1`.

This bundle is the reason the port exists in this form. The RG Nano is a **musl**
system, and the launcher is a glibc binary; rather than port it, NanoCraft ships
glibc and invokes the bundled loader explicitly.

The LGPL is satisfied by dynamic linking plus availability of the unmodified
source below. Nothing here relinks or statically embeds glibc, and the loader is
used as published.

### Obtaining the corresponding source

Every Debian binary above — glibc, LLVM and this table — comes from one pinned
snapshot, the same one the build containers use:

```
https://snapshot.debian.org/archive/debian/20240612T000000Z/
```

On a Debian 10 system, `apt-get source <package>` retrieves it. The snapshot URL
is pinned in the Dockerfiles in `build/`, so the exact sources used are
recoverable rather than approximate.

## Written for this project

## Not redistributed

**FunKey-OS / DrUm78's RG Nano OS.** NanoCraft calls the OS's own `keymap`,
`powerdown`, `volume` and `brightness` helpers and relies on `fkgpiod` and
GMenu2X. Nothing from the OS is included here.

- https://github.com/DrUm78/FunKey-OS

**Raster Forge Regular** is used by `opk/make-menu-bg.sh` to pre-render the quick
menu's text into `menubg.raw`. The font is a **build input only** — no release
archive contains a font file, and only the rendered bitmap ships.
